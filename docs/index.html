Part 1

Online Information

This section explains FastAPI, the role of each component and the design choices used in the Task Manager example.

FastAPI overview

Python types drive validation and documentation

FastAPI is a Python web framework for building APIs. A developer declares routes with decorators and describes data with standard Python type hints and Pydantic models. FastAPI uses those declarations to validate requests, serialize responses and generate an OpenAPI schema.

The schema powers two documentation interfaces included by default: Swagger UI at /docs and ReDoc at /redoc. Swagger UI can send real requests, which makes it useful for development and classroom demonstrations.

How FastAPI works

A request moves through five clear stages

  1. ClientSwagger UI, a browser or another application sends an HTTP request.
  2. UvicornThe ASGI server receives the request and passes it to the application.
  3. FastAPI routeThe HTTP method and path select the matching route function.
  4. Pydantic modelTypes and field rules validate the request data before the function runs.
  5. Repository and responseThe application reads or changes task data, then returns JSON with an HTTP status.

The example repository stores tasks in memory. Restarting the server clears the data. This keeps the lab focused on FastAPI rather than database setup.

Application scenario

A small API for presentation tasks

A student group needs a shared structure for presentation tasks such as checking references, rehearsing the live demo and uploading slides. Each task has a title, an optional description, a workflow status and a priority from 1 to 5. The example keeps the scenario small enough to learn in one lab while still demonstrating a complete REST workflow.

The model defines the API contract

The request body must contain a visible title. Priority accepts values from 1 to 5, and status accepts only the three values in the TaskStatus enumeration. Invalid data receives a 422 response before the route changes any stored tasks.

The excerpt shows field declarations. The complete file also imports its types and uses a validator to reject whitespace-only titles. See the model construction step and Pydantic documentation [5].

Evaluation

FastAPI strengths and limitations

Strengths

  • Type hints support validation, editor assistance and API documentation from the same declarations.
  • Swagger UI gives developers an immediate way to inspect and test routes.
  • ASGI support suits applications that need asynchronous request handling.
  • The framework supports small examples and larger projects split across modules.

Limitations

  • Developers still need to design authentication, authorization and secure deployment.
  • Type hints and asynchronous Python can be unfamiliar to beginners.
  • A complete application still needs choices for persistence, migrations and monitoring.
  • In-memory data disappears when the process restarts and cannot support multiple server processes.

Part 2

Online Tutorial Lab Instructions

Complete the steps in order. By the end, you will run the API, create and update a task, observe a validation error and execute the automated tests.

Build it yourself: the development lab walks through the model, repository, routes and tests, with complete files and a checkpoint after every step. Use the steps below to run the finished application first.

Learning outcomes

  • Explain how a FastAPI route maps an HTTP request to Python code.
  • Use Swagger UI to test a REST API.
  • Recognise Pydantic validation and common HTTP status codes.
  • Run automated tests for the example application.
1

Check the prerequisites

Install Python 3.12 or later and Visual Studio Code. Download or clone the coursework repository, then open its fastapi-cw1 folder in VS Code.

Checkpoint: Open a PowerShell terminal in VS Code and run python --version. A Python version should appear.
2

Create an isolated environment

Run these commands from the fastapi-cw1 folder. The virtual environment keeps this project's packages separate from other Python projects.

PowerShell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Checkpoint: The final installation line should complete without an error.
3

Start the FastAPI server

Move into the application folder and start Uvicorn with automatic reload for development.

PowerShell
cd fastapi-project
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
Checkpoint: The terminal should show Uvicorn running on http://127.0.0.1:8000. Keep this terminal open.
4

Open the generated documentation

Open http://127.0.0.1:8000/docs. Expand GET /tasks, select Try it out, then select Execute.

The first response should be an empty JSON array because the in-memory repository starts without tasks.

[]
Checkpoint: Confirm the response status is 200.
5

Create a task

Expand POST /tasks, select Try it out and replace the example body with the JSON below.

JSON request body
{
  "title": "Rehearse the FastAPI demo",
  "description": "Practise the Swagger UI workflow",
  "status": "todo",
  "priority": 5
}

Select Execute. FastAPI validates the body and the repository assigns an identifier and timestamps.

Checkpoint: Confirm the response status is 201 and note the returned task id.
6

Observe validation

Send another POST /tasks request, but change priority to 9. The model only allows values from 1 to 5.

Invalid JSON request body
{
  "title": "Invalid priority example",
  "status": "todo",
  "priority": 9
}
Checkpoint: Confirm the response status is 422. Read the error location and constraint in the response body.
7

Read and update the task

Use GET /tasks/{task_id} with the identifier from Step 5. Then use PUT /tasks/{task_id} with the body below.

Replacement JSON body
{
  "title": "Rehearse the FastAPI demo",
  "description": "Swagger UI workflow completed",
  "status": "done",
  "priority": 5
}

Finally, call GET /tasks?status=done. The query filter should return the updated task.

Checkpoint: Confirm the updated task has status: "done".
8

Delete the task and inspect the error

Call DELETE /tasks/{task_id}. A successful delete returns status 204 with no response body. Call GET /tasks/{task_id} again.

Checkpoint: The second request should return 404 with a message that the task was not found.
9

Run the automated tests

Open a second PowerShell terminal in fastapi-project and run the test suite. TestClient creates an isolated app, so Uvicorn can stay open. You can also stop the server with Ctrl + C if finished.

PowerShell
..\.venv\Scripts\python.exe -m pytest -q
Checkpoint: The project should report 8 passed. The tests cover documentation, CRUD operations, filters, validation and error responses.

Troubleshooting

Common setup problems

python is not recognised

Install Python and select the option that adds Python to PATH. Restart VS Code after installation.

PowerShell blocks Activate.ps1

The tutorial commands call the virtual environment's Python executable directly, so activation is not required.

Port 8000 is already in use

Stop the other process or start Uvicorn with --port 8001, then open http://127.0.0.1:8001/docs.

Tasks disappear after restart

This is expected. The teaching project uses memory storage. Persistent data would require a database such as SQLite.
